# Demo plan (plan only; nothing here is built)

Two pieces: a Gradio app for Hugging Face Spaces that runs on CPU, and an optional "agent with a gate" mode. Effort figures are my estimates for one person who knows this repository, not measurements.

## 1. The Space: "score a tool call"

**What the visitor does.**
1. Picks one of a few **example conversations** (a real test row that the model gets right, one it misses, one false alarm, and a hand-written clean one), or pastes their own.
2. **Edits the conversation or the call** in two boxes: the turns (one line per turn, with a role prefix: `USER:`, `AGENT:`, `CALL: tool(arg=value)`, `RESULT:`) and the candidate call (tool name and arguments as JSON), plus a domain dropdown (retail, airline, telecom).
3. Presses **Score** and sees: the probability that the call is incorrect, a gauge with the three operating points (`fa05` 0.895, `fa10` 0.731, default 0.5) and the decision at the one selected ("flag" or "allow"), **the text the model actually read** (`Verdict.input_text`, with the `POLICY:` line highlighted when the tool has one), the token count, and a notice when the 4,096-token ladder had to cut evidence.
4. Under the result, a fixed note: what the numbers mean (AUROC 0.771 against 0.719 for GPT-5-mini; recall 0.33 at 10% false alarms) and that the score is not calibrated and reacts to phrasing (the probes of D-031), so a single example proves nothing.

**Sketch.**

```
[ example: v ]  [ domain: retail v ]                                [ operating point: fa10 v ]
┌ conversation (editable) ───────────────┐   ┌ result ─────────────────────────────┐
│ USER: ...                              │   │ P(incorrect) 0.02   [====|------]   │
│ CALL: get_order_details(order_id=...)  │   │ decision: ALLOW (threshold 0.731)   │
│ RESULT: {...}                          │   │ tokens 281, nothing cut             │
└────────────────────────────────────────┘   ├ what the model read ────────────────┤
┌ candidate call (editable, JSON) ───────┐   │ TOOLS: ...  POLICY: An order can... │
│ {"name": "cancel_pending_order", ...}  │   │ HISTORY: ...  CANDIDATE: ...        │
└────────────────────────────────────────┘   └─────────────────────────────────────┘
                 [ Score ]        notes on what this score does and does not mean
```

**Pieces.** `app.py` (about 150 lines of Gradio) calling `verifier.predict.load` once at start and `score` per click; a small parser from the line format to turns; `requirements.txt` (CPU `torch`, `transformers`, `gradio`); the model files either in the Space (Git LFS, 600 MB) or on a Hub model repository that the Space downloads; examples as a JSON file. Cost to run: the free CPU tier (from memory, 2 vCPU and 16 GB RAM: **to be checked**); a call took 0.68 s median and 2.3 s at the 95th percentile on a 10-core Mac with 4 threads (D-030), so expect a few seconds, perhaps more, on the shared CPU (not measured). The first request after a sleep also pays the model load.

**Open points that block publishing** (`docs/licenses.md`): the license of the weights; whether real test conversations (τ²-bench text generated by commercial models, with simulated customer data) may be shown. Until those are settled the examples should be hand-written or synthetic. Privacy: visitors will paste conversations; the app should not log them and should say so.

**Effort.** Working version (examples, editing, score, decision, input text, notes, packaging, a smoke test against `check_against_saved`): **about 1 day**. Polish (example curation with honest hits and misses, mobile layout, error messages for malformed input, a clear disclaimer, README of the Space): **+0.5 to 1 day**. Model upload and license decisions are on you and not counted.

## 2. Optional: "agent with a gate" mode

**Idea.** Show the verifier in the loop: replay a τ²-bench conversation and, before each agent tool call, score it; if it is flagged at the chosen operating point, **block** it and show what would have happened.

**Variant A, replay of a recorded run (recommended, runs in the same Space).** Take a recorded trajectory from the test set (agent calls, tool results and our label for the flagged call). Step through it in a timeline: for each agent call show the score and the decision; mark blocked calls in red; show the human label of the call next to the decision (true catch, miss, false alarm) and a summary line for the whole run ("3 calls scored, 1 blocked, the blocked call was the labeled error"). "Blocking" is honest only as annotation: the recorded run continues because the agent never saw the block, and the page says so. Scoring all the calls of one run is one forward pass per call (0.7 s each on a laptop; telecom runs have hundreds of turns but only a few dozen calls). **Effort: about 1 to 1.5 days** on top of the basic Space (a trajectory picker, per-call scoring, the timeline, 3 to 5 curated runs including at least one miss and one false alarm).

**Variant B, a live agent with a real gate (local script or recorded video, not on the free Space).** Run τ²-bench with an LLM agent and user simulator, intercept each tool call, score it, and when it is flagged return a message to the agent ("this call was blocked by the verifier; check the policy and try again"), then measure whether task success and the number of policy violations change. This is the real demonstration of value and the only one that tests the idea, but: it needs a τ²-bench installation (D-019 records the Python-version friction), API keys and money (the induced runs cost about $0.008 per run with gpt-5-nano and gpt-4.1-mini, D-019; a fair comparison needs dozens of runs per condition), and a Space cannot hold keys for anonymous users. The result may be unflattering: at the 10% false-alarm setting the model catches a third of the errors, so most violations pass and 1 in 10 good calls is blocked. **Effort: 3 to 5 days** including a small experiment (50 tasks, gate on and off, same seeds), most of it debugging the agent loop and statistics; a 2-minute screen recording is a cheaper way to show it.

## 3. Recommended order

1. Settle the license and the example policy (your decisions, section 5 of `docs/licenses.md`).
2. Build the basic Space with hand-written examples (1 day), then add 3 to 5 real examples if the license review allows.
3. Add variant A (1 to 1.5 days) if a timeline helps the portfolio story.
4. Only do variant B if you want to claim an effect on task success; it needs its own test and may show none.
